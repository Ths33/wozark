# Backlog — 2026-03-28

## P0 — Broken (não funciona)

### Ruth: METAR delay de ~8min no final de cada hora
- **Problema:** Ruth lê `https://tgftp.nws.noaa.gov/data/observations/metar/cycles/{HH}Z.TXT` usando a hora UTC atual. METARs observados em :52/:53 são publicados pela NOAA no arquivo da hora seguinte. Ruth só muda de arquivo quando a hora vira → delay de até 8min.
- **Impacto:** Perde timing de trade. Edge do sistema é velocidade.
- **Fix:** Ler também o arquivo da hora anterior, ou migrar para API `aviationweather.gov/api/data/metar?ids=XXXX` que retorna o último METAR independente do ciclo.
- **Arquivo:** `wbot-ruth/src/metar/poller.rs`

### Ruth: METARs perdidos durante restart da Wendy
- **Problema:** Se Wendy está em deploy/restart quando Ruth tenta enviar, o METAR é descartado sem fila. Circuit breaker (10 falhas → 30s backoff) dropa tudo silenciosamente.
- **Impacto:** Dados perdidos, trades atrasados.
- **Fix:** Retry queue com TTL curto (30s), ou enviar para fila (Redis/memory) e drenar quando Wendy voltar.
- **Arquivo:** `wbot-ruth/src/sender.rs`

## P1 — Degradado (funciona mal)

### Marty: Dados de market/positions não atualizam via WS
- **Problema:** METAR, PWS e logs são push via WebSocket. Market prices e positions são fetch único no mount, nunca mais atualizam em tempo real. Implementado polling de 30s como workaround (gambiarra).
- **Impacto:** Dashboard mostra preços e P&L desatualizados. Experiência de "real-time" é ilusão.
- **Fix:** Wendy precisa broadcast `market_update` e `position_update` via WS quando prices mudam. Marty reage via Zustand. Remover polling de 30s.
- **Arquivos:** `wbot-wendy/src/server.ts`, `wbot-wendy/src/shared/ws/broadcaster.ts`, `wbot-marty/stores/stations.ts`, `wbot-marty/app/station/[icao]/StationDetail.tsx`

### Jonah: station_check não roda dawn predictions
- **Problema:** Dawn prediction (6am local) depende de `session is None or not session.has_dawn`. Se o scheduler falha ou o app reinicia depois das 6am, o dawn nunca é gerado para o dia.
- **Impacto:** Sem dawn prediction, updates posteriores não rodam (`session.has_dawn` é False).
- **Fix:** Fallback: se não há dawn e já passaram as 6am, gerar como "late dawn" na primeira oportunidade.
- **Arquivo:** `wbot-jonah/src/main.py` (linhas 109-112)

### Jonah: Colunas faltam no DB (timing, range_prob, sources_accuracy)
- **Problema:** `CREATE TABLE IF NOT EXISTS` não adiciona colunas novas a tabelas existentes. `_run_migrations()` foi adicionado mas não logou ter rodado.
- **Status:** Fix deployed, precisa confirmar que migrations correram.
- **Arquivo:** `wbot-jonah/src/db.py`

## P2 — Segurança

### DB ports expostos na internet
- **Problema:** Logs do Jonah DB mostram port scanning externo (`invalid length of startup packet`, `unsupported frontend protocol`). A porta 5432 está acessível publicamente.
- **Fix:** Firewall: bloquear acesso externo às portas dos DBs. Só aceitar conexões da rede interna do CapRover.

### JWT em localStorage (não httpOnly cookies)
- **Problema:** Token JWT armazenado em localStorage, vulnerável a XSS.
- **Fix:** Migrar para httpOnly cookies com SameSite=Strict.

### Rate limiting ausente
- **Problema:** Sem rate limiting no login, endpoints de trading, ou API em geral.
- **Fix:** Adicionar rate limiting no Fastify (login: 5/min, trading: 30/min).

### Jonah endpoints sem auth
- **Problema:** POST /signal do Jonah verifica RUTH_SECRET, mas outros endpoints podem estar abertos.
- **Fix:** Verificar todos os endpoints, restringir a rede interna ou adicionar auth.
